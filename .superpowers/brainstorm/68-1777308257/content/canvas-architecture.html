First question: Canvas architecture

The biggest decision for v0.25 — this shapes everything else

Right now the app has two separate canvas screens: Zone Map (store overview — zones as polygons) and Floor Builder (inside one zone — fixtures). The v0.25 goal of a Figma-like editor raises a fundamental question about how these relate.

A

Unified Canvas

One infinite canvas for the whole store. Zones and fixtures coexist. Zoom in to see fixtures inside a zone; zoom out to see the full floor plan. Like Figma — frames contain elements.

Pros

  • True Figma-like experience
  • No screen switching mid-workflow
  • See context while editing details

Cons

  • Major rearchitecture
  • Replaces both Zone Map + Floor Builder
  • Highest effort (~3× more code)
B

Linked Canvas (recommended)

Zone Map stays as the store overview. Floor Builder gets major UX improvements (smoother drag, resize handles, zoom/pan, planogram badges). Tapping a zone drills into its Floor Builder. The connection between them is explicit and clear.

Pros

  • Builds on working code
  • Delivers the UX wins quickly
  • Each canvas is focused

Cons

  • Context switch when drilling in
  • Not literally a single canvas
C

New Store Canvas (replaces Zone Map only)

Replace Zone Map with a new Store Canvas screen that shows zones + their fixtures together, with store-size grid, zoom/pan, and inline editing. Floor Builder becomes an optional "deep edit" mode. Middle-ground approach.

Pros

  • Unified top-level view
  • Doesn't throw away Floor Builder
  • Moderate effort

Cons

  • Two edit surfaces still exist
  • Risk of duplicating logic

My recommendation is B (Linked Canvas) — it delivers the Figma-like feel where it matters most (smooth fixture editing) without the risk of a full rewrite. But if you want the truly unified experience, A is the right call.
