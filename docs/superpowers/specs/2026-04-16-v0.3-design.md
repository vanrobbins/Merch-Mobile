# Merch Mobile v0.3 Design Spec

**Date:** 2026-04-16  
**Author:** Van Robbins + Claude  
**Status:** Approved

---

## Overview

v0.3 adds the VM merchandising layer on top of v0.2's wired features. The three pillars are:

1. **Product system overhaul** — brand color palettes, product templates with garment silhouettes, default seeded products, and a redesigned creation flow
2. **Mannequin system** — five body types, floor/wall/platform mounting, placed in both Floor Builder and Zone Detail
3. **Mannequin dressing (Mannequin Lock)** — outfit slot assignment from catalog, visible on Zone Detail and Planogram views

Accessories (SKU-bearing catalog items) and scene props (no SKU, purely visual) complete the merchandising scene toolkit.

**Prerequisite:** v0.2 fully merged to main (Agents 1–7 complete).

## 1. Database Schema

### New Tables

#### `brand_colors`
```
id            TEXT PRIMARY KEY
store_id      TEXT NOT NULL REFERENCES stores(id)
name          TEXT NOT NULL          -- e.g. "Preb Blue", "Natural", "Navy"
hex_value     TEXT NOT NULL          -- e.g. "#4A6FA5"
created_at    INTEGER NOT NULL
```

#### `product_templates`
```
id                 TEXT PRIMARY KEY
name               TEXT NOT NULL     -- e.g. "Metal Vent SS", "Slim Chino"
category           TEXT NOT NULL     -- Tops | Bottoms | Outerwear | Accessories | Other
silhouette_type    TEXT NOT NULL     -- shirt_ss | shirt_ls | tank_top | pant | short |
                                     --   jacket | dress | skirt | bag | hat | bra | shoe | other
custom_image_path  TEXT              -- nullable; path to store-uploaded asset
is_default         INTEGER NOT NULL  -- 1 = global built-in (read-only), 0 = store custom
store_id           TEXT              -- nullable; null = global built-in
```

Built-in global templates (store_id = null, is_default = 1) are seeded at app install:
shirt_ss, shirt_ls, tank_top, pant, short, jacket, dress, skirt, bag, hat, bra, shoe, other (13 total).

#### `platforms`
```
id            TEXT PRIMARY KEY
store_id      TEXT NOT NULL REFERENCES stores(id)
zone_id       TEXT NOT NULL REFERENCES zones(id)
width         REAL NOT NULL
depth         REAL NOT NULL
elevation     REAL NOT NULL          -- visual height off floor
position_x    REAL NOT NULL
position_y    REAL NOT NULL
rotation      REAL NOT NULL DEFAULT 0
color_hex     TEXT NOT NULL DEFAULT '#CCCCCC'
created_at    INTEGER NOT NULL
```

#### `mannequins`
```
id               TEXT PRIMARY KEY
store_id         TEXT NOT NULL REFERENCES stores(id)
zone_id          TEXT NOT NULL REFERENCES zones(id)
name             TEXT                -- optional display label
mannequin_type   TEXT NOT NULL       -- full_body | half_body | torso | leg_form | bra_form
mount_type       TEXT NOT NULL       -- floor | wall | platform
platform_id      TEXT                -- nullable REFERENCES platforms(id)
position_x       REAL NOT NULL
position_y       REAL NOT NULL
rotation         REAL NOT NULL DEFAULT 0
outfit_name      TEXT                -- current outfit label (the "Mannequin Lock" name)
outfit_notes     TEXT                -- freetext notes about the current outfit
created_at       INTEGER NOT NULL
```

#### `mannequin_outfit_slots`  *(the Mannequin Lock)*
```
id               TEXT PRIMARY KEY
mannequin_id     TEXT NOT NULL REFERENCES mannequins(id)
body_slot        TEXT NOT NULL       -- head | torso | legs | feet |
                                     --   left_hand | right_hand | accessory_1 | accessory_2
product_id       TEXT                -- nullable REFERENCES products(id)
color_id         TEXT                -- nullable REFERENCES brand_colors(id)
color_notes      TEXT                -- free text if color not in palette
display_notes    TEXT                -- e.g. "tucked in", "rolled sleeves"
created_at       INTEGER NOT NULL
```
`outfit_name` and `outfit_notes` live on the `mannequins` row (one active outfit per mannequin at a time).

Available slots by mannequin type:

| Type | Slots |
|---|---|
| full_body | head, torso, legs, feet, left_hand, right_hand, accessory_1, accessory_2 |
| half_body | torso, left_hand, right_hand, accessory_1, accessory_2 |
| torso | torso, accessory_1, accessory_2 |
| leg_form | legs, feet |
| bra_form | torso |

#### `mannequin_outfit_proposals`
```
id                TEXT PRIMARY KEY
mannequin_id      TEXT NOT NULL REFERENCES mannequins(id)
store_id          TEXT NOT NULL REFERENCES stores(id)
proposed_by_uid   TEXT NOT NULL
proposed_at       INTEGER NOT NULL
status            TEXT NOT NULL      -- pending | approved | rejected
slot_changes      TEXT NOT NULL      -- JSON snapshot of proposed outfit slots
notes             TEXT
reviewed_by_uid   TEXT
reviewed_at       INTEGER
```

#### `scene_props`
```
id            TEXT PRIMARY KEY
store_id      TEXT NOT NULL REFERENCES stores(id)
zone_id       TEXT NOT NULL REFERENCES zones(id)
prop_type     TEXT NOT NULL          -- plant | furniture | riser | signage | other
name          TEXT NOT NULL
position_x    REAL NOT NULL
position_y    REAL NOT NULL
rotation      REAL NOT NULL DEFAULT 0
width         REAL NOT NULL
depth         REAL NOT NULL
created_at    INTEGER NOT NULL
```

### Modified Tables

#### `products` (existing) — new columns via migration
```
template_id   TEXT     -- nullable REFERENCES product_templates(id)
color_id      TEXT     -- nullable REFERENCES brand_colors(id)
color_notes   TEXT     -- free text fallback when color not in palette
price         REAL     -- nullable
image_path    TEXT     -- nullable; path to product photo
```

## 2. Brand Color Palette

### ColorPaletteScreen

Located under Store settings, accessible to coordinator and manager. Displays named color swatches in a grid. Actions:
- **Add color** — enter name + hex value (or use system color picker); saved to `brand_colors`
- **Edit** — tap swatch to edit name or hex
- **Delete** — swipe-to-delete; warns if color is in use by products or outfit slots

Staff see a read-only palette view (no edit controls).

### Color Picker Widget (`MmColorPicker`)

Reusable widget used in the product form and mannequin dressing sheet:
- Row of brand palette chips (name + color swatch); selecting sets `color_id`
- "Other" chip at end opens a hex input + `color_notes` text field
- Selected color renders as a chip on the product card and in Mannequin Lock displays

## 3. Product Templates

### ProductTemplateScreen

Coordinator/manager only. Two sections:
- **Built-in** — 11 global silhouettes (read-only tiles with silhouette preview)
- **Store Custom** — store-specific templates; add via upload (image_picker) or by naming a built-in silhouette variant

Custom templates store `store_id` and optionally `custom_image_path`.

### Silhouette Assets

13 SVG assets bundled in `assets/silhouettes/`: `shirt_ss.svg`, `shirt_ls.svg`, `tank_top.svg`, `pant.svg`, `short.svg`, `jacket.svg`, `dress.svg`, `skirt.svg`, `bag.svg`, `hat.svg`, `bra.svg`, `shoe.svg`, `other.svg`. Rendered via `flutter_svg`.

## 4. Product System Overhaul

### Redesigned ProductFormScreen (3-step flow)

**Step 1 — Template**
- Scrollable grid of silhouette tiles (built-in + store customs)
- Selecting a template previews the silhouette above the form and auto-fills the product name (editable)

**Step 2 — Color**
- `MmColorPicker` widget
- Selecting a palette color sets `color_id`; "Other" sets `color_notes`

**Step 3 — Details**
- SKU (auto-suggested as `TEMPLATE_CODE-COLOR_CODE`, e.g. `MVS-PB01`; fully editable)
- Stock qty (existing)
- Price (new field)
- Optional photo upload via image_picker → `image_path`

### Default Products at Store Creation

When a store is created (Agent 1 `CreateStoreScreen` flow), a `seedDefaultProducts(storeId)` function inserts 20 pre-built products (4 tops, 4 bottoms, 2 outerwear, 4 accessories, 3 dresses, 3 shorts) using global templates and a 5-color default palette (White `#FFFFFF`, Black `#1A1917`, Navy `#1B2A4A`, Grey `#9E9890`, Khaki `#C8B89A`). These default colors are also inserted into `brand_colors` for the store. Coordinators can edit or delete these. Purpose: demonstrate catalog structure on first launch.

### Accessories

Accessories are standard catalog products with `category = "Accessories"`. No separate table. They appear in `ProductSlotPicker` when filling mannequin accessory slots (filtered by category). They can also be assigned to planogram fixture slots like any other product.

## 5. Mannequin Placement

### Floor Builder Integration

The add FAB becomes a segmented speed-dial with four options:
- **Fixture** — existing flow
- **Mannequin** — opens type picker bottom sheet (5 type tiles with icons + labels)
- **Platform** — opens dimension input sheet (width, depth, elevation, color)
- **Prop** — opens prop type picker (plant, furniture, riser, signage, other) + name field

After placing, each element renders on the canvas with the same drag/rotate/delete handle pattern as existing fixtures.

**Mannequin canvas rendering:**
- Icon: stylized figure with a type badge (FB, HB, T, L, BF)
- Color: neutral `#888888` fill with accent border when selected
- Wall-mounted: half-circle flush against the polygon edge with inward-facing arrow

**Platform canvas rendering:**
- Filled rectangle with `color_hex` + elevation label ("↑ 12in")
- Mannequins placed on a platform draw offset above it in z-order

**Prop canvas rendering:**
- Rounded rect with prop-type icon + name label

### Zone Detail Integration

Display zones show a second section below the fixture list: **Mannequins**. Each row:
- Type badge + mannequin name (or "Unnamed")
- Outfit lock summary: color swatch row of filled slots, or "No outfit" placeholder
- **Dress** button → opens `MannequinDressingSheet`

### Wall Snap Gesture

When dragging a mannequin with `mount_type = wall`, proximity within 20px of any zone polygon edge triggers a snap. The mannequin locks to that edge and its rotation aligns perpendicular to the edge (facing inward). Valid only for half_body, torso, bra_form types.

## 6. Mannequin Dressing (Mannequin Lock)

### MannequinDressingSheet

Full-screen bottom sheet (DraggableScrollableSheet). Two-panel layout:

**Left panel — Silhouette diagram**
- SVG body outline scaled to mannequin type
- Tappable region per available slot
- Filled slot: renders assigned product's `color_id` hex as a fill zone
- Empty slot: dashed outline + "+" icon

**Right panel — Slot list**
- Scrollable list of available slots for the mannequin type
- Each row: slot label | product name + color chip | Edit icon | Clear icon
- Tapping row or silhouette region opens `ProductSlotPicker` filtered by slot category:
  - head → Accessories
  - torso → Tops, Outerwear
  - legs → Bottoms
  - feet → Accessories
  - hands → Accessories
  - accessories → Accessories

**Header:**
- Outfit name text field (editable; defaults to mannequin name)
- Freetext notes field

### MannequinLockCard Widget

Displays on Zone Detail mannequin rows and on Planogram views:
```
[Outfit Name]
Head:    SKU-001 — WHITE
Torso:   SKU-042 — PREB BLUE
Legs:    SKU-118 — KHAKI
```
Color name displayed in ALL CAPS. Unassigned slots omitted from the card.

### Role Rules

| Role | Action |
|---|---|
| Coordinator / Manager | Direct save to `mannequin_outfit_slots` |
| Staff | Creates `mannequin_outfit_proposals` row; manager/coordinator reviews via `OutfitProposalReviewScreen` |

## 7. Canvas Layer Order (Floor Builder)

Four `CustomPainter` passes in z-order:
1. Zone polygon (background fill + stroke)
2. Platforms (filled rectangles with elevation label)
3. Fixtures + Props (existing fixture rendering + new prop shapes)
4. Mannequins (above all; platform-mounted mannequins offset above platform bounds)

Hit-testing is per-layer so tapping a mannequin on a platform selects the mannequin, not the platform.

## 10. Canvas Interaction Improvements (Agent 3)

### Undo / Redo (Floor Builder)

Command pattern. Each mutating action (add, move, delete) on fixtures, mannequins, platforms, or props creates an `UndoableCommand` with `execute()` and `undo()` methods. `FloorBuilderState` maintains `undoStack` and `redoStack` (max 20 entries each). The redo stack is cleared on any new command.

`FloorBuilderNotifier` exposes `undo()` and `redo()` methods. Two icon buttons in the `FloorBuilderScreen` AppBar (↩ / ↪) are disabled when the respective stack is empty.

Commands to implement:
- `MoveFixtureCommand(before: Fixture, after: Fixture)`
- `AddFixtureCommand(fixture: Fixture)`
- `DeleteFixtureCommand(fixture: Fixture)`
- `MoveMannequinCommand(before: Mannequin, after: Mannequin)`
- `AddMannequinCommand(mannequin: Mannequin)`
- `DeleteMannequinCommand(mannequin: Mannequin)`
- `AddPlatformCommand`, `DeletePlatformCommand`
- `AddScenePropCommand`, `DeleteScenePropCommand`

### Multi-select Fixtures

`FloorBuilderState` gains `selectedFixtureIds: Set<String>` (replaces `selectedFixtureId`) and `isMultiSelectMode: bool`.

- **Long-press** on a fixture → enters multi-select mode, adds that fixture to `selectedFixtureIds`
- **Tap** another fixture while in multi-select mode → adds it to the set
- **Tap empty canvas** → clears selection, exits multi-select mode
- When `isMultiSelectMode = true`: a bottom action bar appears showing "N selected · DELETE ALL · MOVE GROUP"
- **MOVE GROUP:** pan from any selected fixture moves all selected fixtures by the same delta
- All selected fixtures render a shared dashed selection outline

### Zone Overlap Validation

After every zone move (`onPanEnd`) or vertex reshape (`onPanEnd`), run a polygon intersection check across all zones in the canvas.

- Uses the Separating Axis Theorem (SAT) on each zone polygon pair
- Overlapping zone IDs are tracked in the zone canvas state as `overlappingZoneIds: Set<String>`
- Affected zones are rendered with a semi-transparent red warning fill (`Colors.red.withOpacity(0.2)`) and a red stroke
- Non-blocking — does not prevent the move
- Warning clears as soon as the overlap is resolved

## 12. Out of Scope for v0.3

- Firebase sync for new tables
- Cross-store mannequin outfit reporting
- Outfit history / change log
- 3D rendering or AR placement
- Mannequin inventory tracking (how many physical mannequins a store owns)
- Barcode scanning for product creation
