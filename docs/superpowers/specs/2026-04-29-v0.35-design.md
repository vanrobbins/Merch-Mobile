# Merch Mobile v0.35 Design Spec

**Date:** 2026-04-29
**Author:** Van Robbins + Claude
**Status:** Approved
**Branch:** feature/v0.35 (from feature/v0.3)

## Overview

v0.35 adds three capabilities that complete the merchandising workflow:

1. **Undo/Redo (Delta Stack)** — 20-step history for floor builder and planogram editor. Targeted Firestore counter-patches; real-time sync preserved.
2. **AutoBuild enhancements** — smarter algorithm, user controls (density + style), mannequin output, and a Firestore-backed preset library.
3. **Planogram Editor** — dedicated editor screen with fixture-type-aware views (wall bay vs grid), standalone planograms (no fixture required), rich slot presentation (face-out / shoulder-out / folded), drag-to-span, rotation, and per-row bar vs shelf distinction.

**Prerequisite:** v0.3 Agents 1–6 complete and merged.

## Feature 1 — Undo / Redo (Delta Stack)

### Mechanism

One generic record covers every operation type. Before/after stored as serialized Firestore maps (`Map<String, dynamic>?`) so one record type works across Fixture, Mannequin, Platform, and SceneProp without a union type:

```dart
class UndoEntry {
  final List<Map<String, dynamic>?> before; // null = item didn't exist (add op)
  final List<Map<String, dynamic>?> after;  // null = item was deleted
  final List<String> ids;                   // Firestore doc IDs
  final String collection;                  // e.g. 'fixtures', 'mannequins'
  final String label;                       // "Move fixture", "Delete 3 fixtures", …
}
```

Every mutating method is wrapped by `_recordAndExecute()`:
1. Capture before-state of affected doc(s)
2. Execute the existing Firestore write
3. Push `UndoEntry` to `_undoStack` (cap at 20, drop oldest)
4. Clear `_redoStack`

`undo()` pops from `_undoStack`, applies `before` back to Firestore (batch for multi-doc entries), pushes to `_redoStack`.
`redo()` is the inverse.
Both are async and wrapped in try/catch to prevent stack corruption on network error.

### Floor builder scope

`FloorBuilderNotifier` gains private fields (not serialized into state):
- `_undoStack: List<UndoEntry>` (max 20, internal to notifier)
- `_redoStack: List<UndoEntry>` (internal to notifier)

`FloorBuilderState` gains two derived booleans only:
- `canUndo: bool`
- `canRedo: bool`

This keeps the undo stacks out of Firestore-stream-driven state — they are local to the notifier and survive stream updates without being reset.

Operations covered:
- Fixture: add, move, rotate, resize, delete, multi-select delete
- Planogram assignment: assign front, assign back, clear
- Mannequin: add, delete
- Platform: add, delete
- Scene prop: add, delete

### Planogram editor scope

`PlanogramEditorNotifier` maintains a simpler stack: `List<({String before, String after})>` (max 20). Since all slot data lives in the single `slotsJson` field, undo is a single `.update({'slotsJson': entry.before})`.

Also tracks `rowsJson` changes (row type toggles) with the same before/after pattern.

### UI

Two AppBar action buttons in both `FloorBuilderScreen` and `PlanogramEditorScreen`:
- **↩ UNDO** — disabled (greyed) when `canUndo` is false
- **↪ REDO** — disabled when `canRedo` is false
- Long-press either button shows the stack label (e.g., "Undo: Move fixture")

## Feature 2 — AutoBuild Enhancements

### New controls

Three new controls added to `AutoBuildScreen`, below the existing season selector:

| Control | Values | Effect |
|---|---|---|
| STYLE | Wall-Heavy / Mixed / Center Grid | Determines which layout zones are populated |
| DENSITY | Low / Medium / High | Spacing between fixtures: 4 ft / 2 ft / 1.5 ft |
| INCLUDE MANNEQUINS (toggle) | on / off | Adds 1 / 2 / 3 mannequins to suggested output at Low / Medium / High density |

`AutoBuildState` gains: `layoutStyle: LayoutStyle`, `density: LayoutDensity`, `includeMannequins: bool`, `suggestedMannequins: List<Mannequin>`.

### Algorithm changes

`computeAutoLayout` branches on `layoutStyle`:
- **Wall-Heavy** — perimeter fixtures only (no center grid)
- **Mixed** — perimeter + center grid (current behavior)
- **Center Grid** — center tables only (no perimeter)

Spacing constant driven by `density` enum.

Zone bounds: load `zone.shapePoints` from Firestore, compute bounding box from polygon vertices. Replaces the hardcoded 40×30 ft fallback.

Mannequin placement (when toggled on): place 1–3 `Mannequin` objects at evenly-spaced positions in the zone interior, `mountType: 'floor'`, `mannequinType: 'full_body'`. Added to `state.suggestedMannequins`. `applyAutoLayout` batch-writes both fixtures and mannequins.

### Preset library

Presets move from `SharedPreferences` to Firestore: `stores/{storeId}/autoBuildPresets/{presetId}`.

Each preset stores **settings only** (not generated fixtures):
```
{
  id, name, season, layoutStyle, density, includeMannequins, createdByUid, createdAt
}
```

New `FirestoreRefs.autoBuildPresets(storeId)` helper.

UI: **PRESETS** button in `AutoBuildScreen` AppBar opens a `PresetsSheet` (DraggableScrollableSheet):
- Lists presets as dark tiles (name + settings summary)
- **LOAD** on each tile: fills controls + triggers `computeAutoLayout` automatically
- Swipe-to-delete (coordinator/manager only via `RoleGuard`)
- **SAVE CURRENT** button at bottom: saves current control values as a new preset (prompts for name)

## Feature 3 — Planogram Editor

### Data model changes

#### Planogram (updated)

```
fixtureId:       String?   ← now nullable (standalone planograms allowed)
planogramType:   String    ← NEW: 'wall' | 'shelf' | 'table' | 'rack'
rows:            int       ← NEW: number of rows/bays (default 2)
cols:            int       ← NEW: positions per row (default 4)
linearFt:        double?   ← NEW: wall/shelf only (e.g. 8.0)
rowsJson:        String    ← NEW: encodes List<PgRow> (row types + labels)
```

`cols` for wall type is derived on creation: `cols = (linearFt / 2).round()` (one position per 2 ft). User can override.

#### PgRow (new model)

```dart
class PgRow {
  final int index;
  final String rowType;  // 'bar' | 'shelf'
  final String? label;
}
```

Stored in `planogram.rowsJson`. Default: all rows are `'bar'` for wall/shelf/rack, `'shelf'` for table.

#### PgSlot (updated)

```
row:               int       ← NEW: 0-indexed row
col:               int       ← NEW: 0-indexed column within row
presentationMode:  String    ← NEW: 'face_out' | 'shoulder_out' | 'folded'
spanCols:          int       ← NEW: default 1, max 4
spanRows:          int       ← NEW: default 1, max rows count
rotation:          int       ← NEW: 0 | 90 | 180 | 270 (degrees)
colorHex:          String?   ← NEW: brand color hex applied to SVG fill
sectionLabel:      String?   ← NEW: optional row label override per slot
```

Default `presentationMode` by fixture type:
- `wall` → `face_out`
- `shelf`, `rack` → `shoulder_out`
- `table` → `folded`

When row type is `'shelf'`, unassigned slots default to `folded`. When row type is `'bar'`, unassigned slots default to fixture-type default above.

### SVG silhouette rendering

Three rendering modes, all using the existing 13 template silhouette types:

| Mode | SVG approach | New assets? |
|---|---|---|
| `face_out` | Existing front silhouettes. Render with a horizontal bracket element drawn in code at top-left. | None |
| `shoulder_out` | Narrow side-profile silhouette with hanger visible from side. | 13 new side-profile SVGs |
| `folded` | Compact rectangular stack showing fold lines + collar peek. | 13 new folded SVGs |

Color fill: apply `slot.colorHex` (from product's linked `brandColor`) as SVG fill color via Flutter's `colorFilter` on `SvgPicture`. Falls back to `AppTheme.surfaceVariant` when no color set.

**Ship order:** `face_out` first (assets exist) → `shoulder_out` → `folded`. Slots without the needed SVG show a color-filled rounded rectangle with label as a placeholder.

### Planogram creation dialog (updated)

Replaces the existing simple title/season dialog:

1. Title (text field)
2. Season (text field)
3. Type: segmented picker — Wall · Shelf · Table · Rack
4. Rows: number field (default 2)
5. Linear Ft: number field — shown only for wall/shelf types (cols auto-derived)
6. Cols: number field — shown for table/rack types (default 4)

`fixtureId` left null on creation. Assigned later via fixture mini-panel if desired.

### PlanogramDetailScreen (updated)

Becomes read-only. Slot cards no longer respond to tap/long-press for coordinator/manager. Instead gains an **EDIT** AppBar action (`RoleGuard`: coordinator/manager only) that navigates to `PlanogramEditorScreen`.

Staff FAB (PROPOSE CHANGE) unchanged.

### PlanogramEditorScreen (new)

Route: `/home/planograms/:planogramId/edit`

AppBar: planogram title (editable inline via tap) · ↩ · ↪ · **SAVE**

Two view modes, selected by `planogram.planogramType`:

#### Wall/Shelf/Rack — Bay view

Renders rows sequentially. Each row has:
- A header showing row index label + BAR | SHELF segmented toggle
- A visual divider: thin rod (3 px, `#1A1917`) for `bar` rows, thick plank (6 px, `#6B6660` with drop shadow) for `shelf` rows
- A horizontal row of slot cells

Slot cells:
- Filled: shows scaled SVG silhouette in brand color + product name + mode indicator (FACE / SHOULDER / FOLD)
- Empty: dashed border + `+` tap target
- Spanning slot: merges the cells it occupies via grid `columnSpan`/`rowSpan`. Blocked cells are greyed with a lock icon.

#### Table — Grid view

Standard rows × cols grid. No rod/shelf dividers. Product silhouette in each cell, rotated per `slot.rotation`. Rack type also uses the Bay view (rack = U-bar hanging, shoulder-out default) — it is not a grid type.

### Slot interactions

**Tap empty** → `ProductSlotPicker.show()` to assign product. On assignment, `colorHex` is auto-populated from the product's linked brand color.

**Tap assigned** → `ProductSlotPicker.show()` to reassign.

**Long-press assigned** → two things happen simultaneously:
1. Resize handles appear on the active slot:
   - Right edge handle (›) — drag horizontally to set `spanCols` (1–4)
   - Bottom edge handle (˅) — drag vertically to set `spanRows` (1–rows count)
   - Top-right corner (↻) — tap to cycle rotation (0→90→180→270→0)
2. A non-blocking bottom half-sheet slides up (does not cover the slot area) with:
   - **Clear slot**
   - **Presentation** radio: U-Bar (shoulder-out) · Face-out · Folded
   - **Rotate 90°** (same as tapping ↻ handle — both work)

The half-sheet occupies the bottom ~35% of the screen. The slot and its handles remain visible and interactive above it. Tap anywhere outside both the slot and sheet to dismiss and deactivate resize mode.

Every slot change (assign, clear, span, rotate, presentation) is captured by the undo delta stack (before/after `slotsJson` + `rowsJson` snapshot).

### Routes

```
/home/planograms/:id           → PlanogramDetailScreen (read-only, existing)
/home/planograms/:id/edit      → PlanogramEditorScreen (NEW)
/home/planograms/:id/proposals → ProposalReviewScreen (unchanged)
```

## Key Decisions

### Delta Stack over Command Pattern
Rationale: one generic `UndoEntry<T>` vs ~15 command subclasses. Less code, same targeted Firestore patching, easier to extend to new element types.

### Planograms standalone (fixtureId nullable)
Rationale: real merchandising workflows create planograms in planning sessions before floor layouts are finalized. Fixture assignment is optional at creation, wired later via fixture mini-panel.

### Presets to Firestore (not SharedPreferences)
Rationale: multi-user retail teams share layouts across devices. SharedPreferences is per-device only.

### SVG rendering via colorFilter
Rationale: single SVG asset per template, brand color applied at render time via Flutter's `ColorFilter.mode`. No duplicate colored assets.

### Ship order for SVG modes
Rationale: `face_out` uses existing assets and ships with Agent 4. `shoulder_out` and `folded` need new assets (Agent 5). Slots fall back to a color-filled placeholder until assets are ready, so the editor is fully usable from day one.

### PgRow stored in rowsJson
Rationale: Firestore is schemaless — storing row metadata as a JSON field on the planogram doc (alongside `slotsJson`) keeps all planogram layout data in one document, avoiding an extra subcollection.
