# v0.4 Design Spec — UI/UX Unification, Code Simplification & Dependency Updates

**Date:** 2026-04-29  
**Branch:** `feature/v0.4`  
**Type:** Pure polish/refactor — no new user-facing features  
**Milestone:** Unified design system, Apple HIG–inspired aesthetics, simplified codebase, updated dependencies

---

## Overview

v0.4 is a comprehensive polish and refactor pass. No new screens or Firestore collections. Every change serves one of three goals:

1. **Design unification** — consistent visual language across all screens (color, shape, typography, spacing)
2. **Code simplification** — reduce duplication, extract shared widgets, eliminate anti-patterns, shrink file sizes
3. **Dependency hygiene** — bump outdated packages, remove workarounds, align with current Flutter/Dart best practices

---

## Design Direction

**Apple HIG–inspired dark premium.** Keep Flutter/Material as the rendering foundation — no Cupertino widget swap — but apply Human Interface Guidelines principles throughout: large titles, system font, generous radius, thin-line tab bar, subtle depth via surface layering rather than heavy shadows.

**Dark + light mode.** Both modes ship together. Mode driven by `MediaQuery.platformBrightnessOf` with a manual override persisted in SharedPreferences.

## 1. Color System

All colors stored as `AppColors` — a `ThemeExtension<AppColors>` on `ThemeData`. Access everywhere via `Theme.of(context).extension<AppColors>()!`. The old static `AppTheme.*` constants are replaced entirely.

### Dark Mode

| Token | Value | Usage |
|---|---|---|
| `background` | `#252422` | Scaffold background |
| `surface` | `#2E2B28` | AppBar, tab bar, sheet handles |
| `surfaceElevated` | `#363330` | Cards, list containers, inputs |
| `divider` | `#3E3B38` | Horizontal rules, list separators, borders |
| `textPrimary` | `#EBE5DC` | Body text, titles |
| `textSecondary` | `#847D78` | Subtitles, metadata, secondary labels |
| `textHint` | `#504C49` | Inactive tab labels, placeholder text |

**Design rationale:** Backgrounds use a warm grey-brown undertone (red+green bias) matching the temperature of `textPrimary` and `accent`. Previous `#252729` had a cool blue-grey undertone that conflicted with the warm cream text.

### Light Mode

| Token | Value | Usage |
|---|---|---|
| `background` | `#C8C0B4` | Scaffold background |
| `surface` | `#D6CEC4` | AppBar, tab bar |
| `surfaceElevated` | `#E0D8CE` | Cards, list containers, inputs |
| `divider` | `#C0B8AE` | Separators, borders |
| `textPrimary` | `#1E2020` | Body text, titles |
| `textSecondary` | `#88837C` | Subtitles, metadata |
| `textHint` | `#A8A09A` | Inactive labels, placeholders |

### Shared (both modes)

| Token | Value | Usage |
|---|---|---|
| `accent` | `#C4935A` | CTA fills, active icons, selected fills, alert stat numbers |
| `accentDeep` | `#9B6A3A` | Text-on-light only (tab labels, inline links) — 4.1:1 contrast on surfaceElevated |
| `navy` | `#3A4A5C` | Zone type chips, info badges, floor builder zone overlays (20% opacity) |
| `error` | `#A8442A` | Error states, destructive actions |
| `success` | `#3A7A54` | Success states, approved proposals |

**Contrast notes:**
- `textPrimary` on `surfaceElevated` dark: ~12:1 ✓
- `textPrimary` on `surfaceElevated` light: ~8:1 ✓
- `accent` fills on dark `background`: decorative use only
- `accentDeep` on light `surfaceElevated`: ~4.1:1 — passes WCAG AA for normal text ✓

### Accent usage rules
- `accent` (#C4935A): fills, icon colors, CTA button backgrounds, active tab icons
- `accentDeep` (#9B6A3A): text labels on light surfaces only — never on dark
- Never use `accent` as body text color on any surface

## 2. Typography

**Font:** System font — no custom import. SF Pro on iOS, Roboto on Android. Set by omitting `fontFamily` in `ThemeData` and not specifying it in any `TextStyle`. Feels native on each platform, zero bundle overhead.

**Type scale** — values unchanged from v0.3, letterSpacing standardized:

| Token | Size | Weight | Usage |
|---|---|---|---|
| `typeXs` | 10 | w700 | Eyebrow labels — ALL CAPS, letterSpacing 1.2 |
| `typeSm` | 12 | w400 | Secondary text, subtitles, metadata |
| `typeMd` | 14 | w400/w500 | Body, list tile titles |
| `typeLg` | 16 | w600 | Section titles, card headings |
| `typeXl` | 20 | w700 | Screen sub-headings |
| `typeHeading` | 26 | w700 | Large title (AppBar collapsed: 14 centered) |

**Apple large title pattern:**
- List screens (`PlanogramListScreen`, `CatalogScreen`, `PhotoListScreen`, `ZoneMapScreen`, `DashboardScreen`): `SliverAppBar` with `expandedHeight: 88`, large title 26px left-aligned, collapses to 14px centered on scroll.
- Detail screens: standard `AppBar`, title 14px centered ALL CAPS — unchanged.
- Store name shown as 10px eyebrow above large title on `DashboardScreen`.

## 3. Shape System

Replace the single `borderRadius = 2.0` token with a five-level scale. Old `radiusSm/Md/Lg` removed.

| Token | Value | Used for |
|---|---|---|
| `radiusCard` | `12.0` | Cards, bottom sheets, dialogs, modals |
| `radiusCta` | `10.0` | Buttons, text fields, picker sheets |
| `radiusBadge` | `6.0` | Status badges, role tags, small chips |
| `radiusXs` | `4.0` | Tiny indicators, divider caps |
| `radiusPill` | `100.0` | Category chips, toggle pills |

All values live in `DesignTokens`. `AppTheme.borderRadius` constant removed.

## 4. Navigation Shell

### Bottom tab bar
Replace `BottomNavigationBar` with `NavigationBar` (Material 3). The old widget is deprecated in M3 and produces analyzer warnings.

**Styling:**
- `backgroundColor`: `colors.surface`
- Top border: `0.5px solid colors.divider` (no elevation shadow)
- Active icon color: `colors.accent`
- Active label color: `colors.accent` (dark) / `colors.accentDeep` (light)
- Inactive icon + label: `colors.textHint`
- Label style: 9px, w600, letterSpacing 0.3 — matches Apple tab bar
- `indicatorColor: Colors.transparent` — no pill indicator, icon color carries the active state
- Height: default M3 NavigationBar height (~80px including safe area)

### AppBar
- Background: `colors.surface` (not hardcoded `AppTheme.primary`)
- Foreground: `colors.textPrimary`
- Elevation: 0
- AppBar title → ALL CAPS 14px centered on detail screens (unchanged)
- List screens → `SliverAppBar` large title (see §2)

### Navigation pattern
All `Navigator.push` / `MaterialPageRoute` calls replaced with `context.goNamed(AppRoutes.x)`. Affected screens:
- `CatalogScreen` → `ColorPaletteScreen`, `ProductFormScreen`, `ProductTemplateScreen`
- Any other push-style navigation found during Agent 2 sweep

## 5. Shared Widget Catalog

All shared widgets live in `lib/core/widgets/`. Feature files may not define local variants of these.

### Updated widgets

**`AppScaffold`**
- Swap `BottomNavigationBar` → `NavigationBar`
- Apply token colors, 0.5px divider border-top, transparent indicator
- No other structural changes

**`MmCard`**
- `borderRadius`: 2px → `radiusCard` (12px)
- `color`: `Colors.white` → `colors.surfaceElevated`
- `boxShadow`: tuned per mode — dark: `0 1px 3px rgba(0,0,0,0.25)`, light: `0 1px 4px rgba(30,32,32,0.08)`
- `border`: `0.5px solid colors.divider` added

**`MmChip`**
- `borderRadius`: `radiusPill` (100px)
- Selected: `colors.accent` fill, cream/dark text
- Unselected: `colors.surfaceElevated` fill, `colors.textSecondary` text
- Replaces the local `_CategoryChip` in `CatalogScreen` — that class is deleted

**`MmBottomSheet`**
- Drag handle: 4×36px, `colors.divider`, centered, 8px top padding
- Background: `colors.surface`
- `borderRadius`: `radiusCard` top corners only
- All `showModalBottomSheet` calls across the app pass `backgroundColor: Colors.transparent` and use this wrapper

**`MmEmptyState`**
- Icon color: `colors.textHint` (was `colors.textSecondary`)
- CTA button: `MmButton` (see below)

**`MmBanner`**, **`MmSearchBar`**
- Colors updated to tokens, no structural changes

### New widgets

**`MmButton`** — `lib/core/widgets/mm_button.dart`

Replaces the scattered `ElevatedButton.styleFrom(backgroundColor: AppTheme.accent)` and `OutlinedButton.styleFrom(...)` patterns found in 12+ locations.

```dart
MmButton(label: 'SAVE', onPressed: () {})           // filled, accent
MmButton.outlined(label: 'CANCEL', onPressed: () {}) // outlined
MmButton.destructive(label: 'DELETE', onPressed: () {}) // filled, error color
```

All variants: `radiusCta` shape, ALL CAPS label text, 44px minimum height.

**`MmTextField`** — `lib/core/widgets/mm_text_field.dart`

Replaces the mix of `OutlineInputBorder` and `UnderlineInputBorder` across dialogs and sheets. Standard decoration: `OutlineInputBorder` with `radiusCta`, fill `colors.surfaceElevated`, border `colors.divider`, focused border `colors.accent`.

```dart
MmTextField(label: 'Title', controller: ctrl)
MmTextField(label: 'Search', hint: 'SKU or name…', onChanged: onSearch)
```

**`MmDialog`** — `lib/core/widgets/mm_dialog.dart`

Wraps `showDialog` + `AlertDialog`. Standardizes: background `colors.surfaceElevated`, `borderRadius: radiusCard`, title 14px bold, body 13px `textSecondary`, actions row uses `MmButton`.

```dart
MmDialog.show(
  context,
  title: 'NEW PLANOGRAM',
  content: Column(...),
  actions: [
    MmButton.outlined(label: 'CANCEL', onPressed: () => Navigator.pop(context)),
    MmButton(label: 'CREATE', onPressed: _submit),
  ],
);
```

Replaces raw `AlertDialog` in: `PlanogramListScreen`, `DashboardScreen` (dimensions dialog), `FloorBuilderScreen`.

**`MmListTile`** — `lib/core/widgets/mm_list_tile.dart`

Apple grouped-list row. Background: `colors.surfaceElevated`. Title: 14px `textPrimary`. Subtitle: 11px `textSecondary`. Trailing: chevron `›` in `textHint`. Internal dividers via `MmListSection` wrapper.

```dart
MmListSection(
  children: [
    MmListTile(title: 'Women\'s Zone', subtitle: '4 fixtures', onTap: () {}),
    MmListTile(title: 'Men\'s Zone', subtitle: '6 fixtures', onTap: () {}),
  ],
)
```

Replaces `Card` + `ListTile` in `PlanogramListScreen`. Used for any grouped list going forward.

**`MmEyebrow`** — `lib/core/widgets/mm_eyebrow.dart`

The ALL-CAPS section header `Text` pattern (`typeXs`, `weightBold`, `letterSpacingEyebrow`, `textSecondary`) appears in 15+ places. Extract to:

```dart
MmEyebrow('STORE OVERVIEW')
MmEyebrow('MANNEQUINS (${count})')
```

## 6. Code Simplification Rules

These rules apply during Agent 2's screen sweep. All are mechanical find-and-replace patterns — no logic changes.

### 6.1 `SizedBox` → `Gap`
`gap` is already in `pubspec.yaml`. Use it.

```dart
// Before
SizedBox(height: DesignTokens.spaceMd)
SizedBox(width: DesignTokens.spaceSm)

// After
Gap(DesignTokens.spaceMd)
Gap(DesignTokens.spaceSm)
```

Apply everywhere: all feature screens, all shared widgets, all bottom sheets.

### 6.2 Hard-coded colors → tokens

All direct `Color(...)`, `Colors.white`, `Colors.grey.*`, `Colors.red.*` references in widget build methods replaced with `AppColors` tokens via `Theme.of(context).extension<AppColors>()!`.

Common violations found in codebase:
- `Colors.white` → `colors.surfaceElevated` (cards) or `colors.textPrimary` (text on dark)
- `Colors.grey.shade200` → `colors.divider`
- `Colors.grey.shade300` → `colors.surfaceElevated`
- `Colors.red.shade600` → `colors.error`
- `Color(0xFF...)` hardcoded in widgets → corresponding token

### 6.3 `Navigator.push` → GoRouter

```dart
// Before
Navigator.push(context, MaterialPageRoute(builder: (_) => const ProductFormScreen()));

// After
context.goNamed(AppRoutes.productForm);
```

Add routes to `app_router.dart` for any screen currently only reachable via `Navigator.push`.

### 6.4 Local widget classes → shared `mm_*`

| Delete | Replace with |
|---|---|
| `_CategoryChip` in `catalog_screen.dart` | `MmChip` |
| `_PlanogramTile` Card+ListTile pattern | `MmListTile` / `MmListSection` |
| Inline `AlertDialog` in `planogram_list_screen.dart` | `MmDialog.show(...)` |
| Inline `AlertDialog` in `dashboard_screen.dart` | `MmDialog.show(...)` |
| Repeated eyebrow `Text(...)` in every screen | `MmEyebrow(...)` |
| `ElevatedButton.styleFrom(backgroundColor: accent)` (12 occurrences) | `MmButton(...)` |
| `OutlinedButton.styleFrom(foregroundColor: accent)` (8 occurrences) | `MmButton.outlined(...)` |
| `ElevatedButton.styleFrom(backgroundColor: errorColor)` | `MmButton.destructive(...)` |

### 6.5 File size targets

Long files broken into smaller focused units:

| File | Current lines | Target | Split strategy |
|---|---|---|---|
| `dashboard_screen.dart` | 508 | < 200 | Extract `_StoreSetupCard` → `store_setup_card.dart`, `_StatsGrid`/`_StatCard` → `stats_grid.dart` |
| `zone_detail_screen.dart` | 614 | < 250 | Extract `_MannequinSection` → `mannequin_section.dart`, `_FixtureEditSheet` → `fixture_edit_sheet.dart` |
| `catalog_screen.dart` | 283 | < 180 | Remove `_CategoryChip` (→ MmChip), simplify with `SliverAppBar` + `MmListSection` |

### 6.6 Consistent async states

All `AsyncValue.when()` blocks use the same structure:

```dart
asyncValue.when(
  data: (data) => _buildContent(data),
  loading: () => const Center(child: CircularProgressIndicator(color: colors.accent)),  
  error: (e, _) => MmEmptyState(
    icon: Icons.error_outline,
    headline: 'Something went wrong',
    body: e.toString(),
  ),
)
```

No more bare `Center(child: Text('Error: $e'))` patterns.

### 6.7 `const` constructors

All widgets with no runtime-variable parameters get `const` constructor calls at the call site. Run `dart fix --apply` as part of Agent 1 to catch these automatically.
