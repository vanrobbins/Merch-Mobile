# v0.4 Design Spec — UI/UX Unification, Code Simplification & Dependency Updates

**Date:** 2026-04-29  
**Branch:** `feature/v0.4`  
**Type:** Pure polish/refactor — no new user-facing features  
**Milestone:** Unified design system, Apple HIG–inspired aesthetics, simplified codebase, updated dependencies

---

## Overview

v0.4 is a comprehensive polish and refactor pass. No new screens or Firestore collections. Every change serves one of four goals:

1. **Design unification** — consistent visual language across all screens (color, shape, typography, spacing)
2. **UX improvements** — fix broken information hierarchy, dead interactions, and structural confusions identified in screen-by-screen audit
3. **Code simplification** — reduce duplication, extract shared widgets, eliminate anti-patterns, shrink file sizes
4. **Dependency hygiene** — bump outdated packages, remove workarounds, align with current Flutter/Dart best practices

---

## Design Direction

**Apple HIG–inspired dark premium.** Keep Flutter/Material as the rendering foundation — no Cupertino widget swap — but apply Human Interface Guidelines principles throughout: large titles, system font, generous radius, thin-line tab bar, subtle depth via surface layering rather than heavy shadows.

**Dark + light mode.** Both modes ship together. Mode driven by `MediaQuery.platformBrightnessOf` with a manual override persisted in SharedPreferences.

## 1. Color System

All colors stored as `AppColors` — a `ThemeExtension<AppColors>` on `ThemeData`. Access everywhere via `Theme.of(context).extension<AppColors>()!`. The old static `AppTheme.*` constants are replaced entirely.

### Dark Mode

| Token | Value | Usage |
|---|---|---|
| `background` | `#252422` | Scaffold background |
| `surface` | `#2E2B28` | AppBar, tab bar, sheet handles |
| `surfaceElevated` | `#363330` | Cards, list containers, inputs |
| `divider` | `#3E3B38` | Horizontal rules, list separators, borders |
| `textPrimary` | `#EBE5DC` | Body text, titles |
| `textSecondary` | `#847D78` | Subtitles, metadata, secondary labels |
| `textHint` | `#504C49` | Inactive tab labels, placeholder text |

**Design rationale:** Backgrounds use a warm grey-brown undertone (red+green bias) matching the temperature of `textPrimary` and `accent`. Previous `#252729` had a cool blue-grey undertone that conflicted with the warm cream text.

### Light Mode

| Token | Value | Usage |
|---|---|---|
| `background` | `#C8C0B4` | Scaffold background |
| `surface` | `#D6CEC4` | AppBar, tab bar |
| `surfaceElevated` | `#E0D8CE` | Cards, list containers, inputs |
| `divider` | `#C0B8AE` | Separators, borders |
| `textPrimary` | `#1E2020` | Body text, titles |
| `textSecondary` | `#88837C` | Subtitles, metadata |
| `textHint` | `#A8A09A` | Inactive labels, placeholders |

### Shared (both modes)

| Token | Value | Usage |
|---|---|---|
| `accent` | `#C4935A` | CTA fills, active icons, selected fills, alert stat numbers |
| `accentDeep` | `#9B6A3A` | Text-on-light only (tab labels, inline links) — 4.1:1 contrast on surfaceElevated |
| `navy` | `#3A4A5C` | Zone type chips, info badges, floor builder zone overlays (20% opacity) |
| `error` | `#A8442A` | Error states, destructive actions |
| `success` | `#3A7A54` | Success states, approved proposals |

**Contrast notes:**
- `textPrimary` on `surfaceElevated` dark: ~12:1 ✓
- `textPrimary` on `surfaceElevated` light: ~8:1 ✓
- `accent` fills on dark `background`: decorative use only
- `accentDeep` on light `surfaceElevated`: ~4.1:1 — passes WCAG AA for normal text ✓

### Accent usage rules
- `accent` (#C4935A): fills, icon colors, CTA button backgrounds, active tab icons
- `accentDeep` (#9B6A3A): text labels on light surfaces only — never on dark
- Never use `accent` as body text color on any surface

## 2. Typography

**Font:** System font — no custom import. SF Pro on iOS, Roboto on Android. Set by omitting `fontFamily` in `ThemeData` and not specifying it in any `TextStyle`. Feels native on each platform, zero bundle overhead.

**Type scale** — values unchanged from v0.3, letterSpacing standardized:

| Token | Size | Weight | Usage |
|---|---|---|---|
| `typeXs` | 10 | w700 | Eyebrow labels — ALL CAPS, letterSpacing 1.2 |
| `typeSm` | 12 | w400 | Secondary text, subtitles, metadata |
| `typeMd` | 14 | w400/w500 | Body, list tile titles |
| `typeLg` | 16 | w600 | Section titles, card headings |
| `typeXl` | 20 | w700 | Screen sub-headings |
| `typeHeading` | 26 | w700 | Large title (AppBar collapsed: 14 centered) |

**Apple large title pattern:**
- List screens (`PlanogramListScreen`, `CatalogScreen`, `PhotoListScreen`, `ZoneMapScreen`, `DashboardScreen`): `SliverAppBar` with `expandedHeight: 88`, large title 26px left-aligned, collapses to 14px centered on scroll.
- Detail screens: standard `AppBar`, title 14px centered ALL CAPS — unchanged.
- Store name shown as 10px eyebrow above large title on `DashboardScreen`.

## 3. Shape System

Replace the single `borderRadius = 2.0` token with a five-level scale. Old `radiusSm/Md/Lg` removed.

| Token | Value | Used for |
|---|---|---|
| `radiusCard` | `12.0` | Cards, bottom sheets, dialogs, modals |
| `radiusCta` | `10.0` | Buttons, text fields, picker sheets |
| `radiusBadge` | `6.0` | Status badges, role tags, small chips |
| `radiusXs` | `4.0` | Tiny indicators, divider caps |
| `radiusPill` | `100.0` | Category chips, toggle pills |

All values live in `DesignTokens`. `AppTheme.borderRadius` constant removed.

## 4. Navigation Shell

### Bottom tab bar
Replace `BottomNavigationBar` with `NavigationBar` (Material 3). The old widget is deprecated in M3 and produces analyzer warnings.

**Styling:**
- `backgroundColor`: `colors.surface`
- Top border: `0.5px solid colors.divider` (no elevation shadow)
- Active icon color: `colors.accent`
- Active label color: `colors.accent` (dark) / `colors.accentDeep` (light)
- Inactive icon + label: `colors.textHint`
- Label style: 9px, w600, letterSpacing 0.3 — matches Apple tab bar
- `indicatorColor: Colors.transparent` — no pill indicator, icon color carries the active state
- Height: default M3 NavigationBar height (~80px including safe area)

### AppBar
- Background: `colors.surface` (not hardcoded `AppTheme.primary`)
- Foreground: `colors.textPrimary`
- Elevation: 0
- AppBar title → ALL CAPS 14px centered on detail screens (unchanged)
- List screens → `SliverAppBar` large title (see §2)

### Navigation pattern
All `Navigator.push` / `MaterialPageRoute` calls replaced with `context.goNamed(AppRoutes.x)`. Affected screens:
- `CatalogScreen` → `ColorPaletteScreen`, `ProductFormScreen`, `ProductTemplateScreen`
- Any other push-style navigation found during Agent 2 sweep

## 5. Screen-Specific UX Improvements

These are structural and interaction fixes — not just style tokens. Agent 2 owns all of them.

### 5.1 Dashboard

**Remove welcome banner entirely.** The gradient card showing `displayName` + role at the top of the screen consumes ~90px of prime real estate with static information. Remove it. The store name becomes the `SliverAppBar` large title; the role eyebrow (`10px, textSecondary`) appears above it.

**Make `_StoreSetupCard` conditional.** It currently renders permanently above the stats grid. Replace with a dismissible `MmBanner` (warning variant) that only appears when `widthFt == null || depthFt == null || entranceJson == null`. Once both dimensions and entrance are set, the banner is gone forever. The store dimensions dialog and entrance navigation links live inside this banner only.

**Wire all dead stat cards:**
- `Fixtures` → remove. Fixtures aren't navigable standalone; fold the count into the `Zones` card subtitle (`4 zones · 18 fixtures`).
- `Proposals` → `context.goNamed(AppRoutes.planogramList)`. The badge dot becomes an accent-colored count badge.
- `Mannequins` → merge into the `Zones` card stat (show both counts or remove the separate card; both nav to `zoneMap`).

**Move logout.** Remove `Icons.logout` from the AppBar actions. Add a `Icons.person_circle_outlined` (or `Icons.account_circle_outlined`) icon button that opens a `MmBottomSheet` containing: display name, role eyebrow, store name, and a destructive `MmButton.destructive(label: 'LOG OUT')`. This prevents accidental logout.

**Urgent stats get visual priority.** When `pendingJoinRequests > 0` or `pendingProposals > 0`, those stat cards use `colors.accent` as their number color and show a filled badge pill (count in accent, not just an 8px dot). Tapping navigates immediately to the relevant screen.

### 5.2 Zone Map

**Replace single-item `PopupMenuButton` with a direct icon button.** The popup has exactly one item ("Edit Entrance"). Replace with `IconButton(icon: Icon(Icons.door_front_door_outlined))` that calls `_enterEntranceEditMode()` directly. Wrapped in `RoleGuard` as before.

### 5.3 Zone Detail — AppBar cleanup

The AppBar currently has: back + title + tune icon + `PROPOSALS` TextButton + `EDIT FLOOR` TextButton. This is too crowded for a 375pt screen.

**New AppBar:** back + zone name + tune icon only.

- `EDIT FLOOR` TextButton is removed — the floor builder merge (being executed separately) makes it redundant.
- `PROPOSALS` TextButton becomes a `Icons.rate_review_outlined` icon button with a count badge overlay when `pendingProposalCount > 0`. Uses `RoleGuard(allowedRoles: ['coordinator', 'manager'])`. Taps to `AppRoutes.outfitProposalReview`.

### 5.4 Edit Zone sheet (`ZonePropertiesPanel`)

**Remove `REPLACE SHAPE`.** Shape replacement is a canvas operation on the zone map, not a metadata property. Remove the button entirely from this sheet. (The zone map canvas already supports vertex dragging to reshape zones.)

**Rename sheet title** from `'EDIT ZONE'` to `'ZONE SETTINGS'`.

**Remove the redundant type subtitle.** There is a `'DISPLAY'` text label rendered between the zone name field and the `'ZONE TYPE'` eyebrow — this shows the currently selected type but is redundant because the chip row already shows it with a checkmark. Remove it.

The cleaned-up sheet contains only: zone name field, zone type chips, color swatches, lock toggle, delete button. This is tight and purposeful.

### 5.5 Catalog

`ColorPaletteScreen` and `ProductTemplateScreen` are navigated via `Navigator.push`. Replace both with `context.goNamed(AppRoutes.colorPalette)` and `context.goNamed(AppRoutes.productTemplate)`. Add both named routes to `app_router.dart`.

### 5.6 Photo List

**Fix the phase bug.** The `FloatingActionButton` calls `PhotoCaptureButton(fixtureId: '', phase: 'before')` hardcoded — the AFTER tab has no capture affordance. Fix: replace the single FAB with per-tab FABs. When the BEFORE tab is active, FAB captures `phase: 'before'`; when AFTER tab is active, FAB captures `phase: 'after'`. Use `TabController.index` to drive the FAB label/phase.

**Fix `TabBar` colors.** `labelColor: Colors.white` and `unselectedLabelColor: Colors.white54` are hardcoded and break in light mode. Replace with `colors.textPrimary` and `colors.textHint`.

**Add approval status overlays on the photo grid.** Each `_PhotoGridItem` should render an `ApprovalStatusChip` as a `Positioned` overlay in the bottom-left corner of the thumbnail so status is visible without tapping through.

### 5.7 Photo Detail

**Use a meaningful AppBar title.** Replace `'PHOTO DETAIL'` with the fixture label or zone name if available, falling back to the formatted capture date (e.g. `'APR 15, 10:23 AM'`). The title information is available from the `PhotoDoc` model.

### 5.8 Members

`MembersScreen` is only reachable via the Dashboard "Join Requests" stat card. Coordinators managing staff need this frequently.

**Add to AppScaffold tab bar** as a 5th or contextual tab — OR surface it via the profile/account sheet (§5.1 logout redesign). Recommended: add a `Icons.people_outline` icon to the profile sheet with a badge count when pending requests > 0, so coordinators have a direct path from any screen without requiring a Dashboard visit.

**Fix silent loading/error states.** The pending members section renders `SizedBox()` on loading and error. Replace with `CircularProgressIndicator(color: colors.accent)` for loading and `MmEmptyState` for error.

### 5.9 Planograms

**`PlanogramListScreen`:**
- Replace `_PlanogramTile` (Card + ListTile) with `MmListTile` / `MmListSection`. The current Card wrapper creates double-elevation artifacts.
- Replace the raw `AlertDialog` + `StatefulBuilder` creation form with `MmDialog.show(...)`. The StatefulBuilder pattern is preserved inside the content widget.
- Replace inline `ElevatedButton.styleFrom` with `MmButton`.

**`PlanogramDetailScreen`:**
- EDIT action: the `TextButton('EDIT', style: TextStyle(color: Colors.white))` in the AppBar is invisible in light mode. Replace with `IconButton(icon: Icon(Icons.edit_outlined))` wrapped in `RoleGuard(allowedRoles: ['coordinator', 'manager'])`. Tapping opens the `PlanogramEditorScreen`.
- Staff PROPOSE CHANGE FAB: currently `Navigator.push(context, MaterialPageRoute(...))`. Replace with `context.goNamed(AppRoutes.proposalReview, extra: planogramId)`.
- `_SlotCard`: replace `Colors.grey.shade200` with `colors.divider`, replace deprecated `.withOpacity()` calls with `.withValues(alpha: ...)`, and replace any other hardcoded colors with tokens.

**`PlanogramEditorScreen`:**
- Rename affordance: the AppBar title is a `GestureDetector` — tapping it opens a rename dialog, but there is no visual cue. Replace with `Row(title, Icon(Icons.edit_outlined, size: 14, color: colors.textHint))` inside the GestureDetector so the edit intent is visible.
- SAVE action: the `TextButton('SAVE', style: TextStyle(color: accent))` in the AppBar trailing area should be `MmButton(label: 'SAVE', ...)` or an `IconButton(Icons.check)` consistent with other editor screens.
- Slot action sheet: currently uses `PersistentBottomSheetController`. Wrap its content in `MmBottomSheet` for consistent drag handle and surface styling.

**`ProposalReviewScreen`:**
- `_ProposalStatusChip`: `Colors.green.shade600` → `colors.success`, `Colors.red.shade600` → `colors.error`, `Colors.amber.shade700` → `colors.accent`. Use `radiusBadge` for the chip shape.
- `_ProposalCard` APPROVE/REJECT buttons: replace inline `ElevatedButton(backgroundColor: green)` and `OutlinedButton(foregroundColor: red)` with `MmButton(label: 'APPROVE')` and `MmButton.destructive(label: 'REJECT')`.
- Raw UID display: `'Proposed by ${proposal.proposedByUid}'` shows a Firebase UID. Resolve the display name from the store membership list (`currentMembershipProvider` or equivalent). Fall back to `'Unknown member'` if not found.

## 7. Code Simplification Rules

These rules apply during Agent 2's screen sweep. All are mechanical find-and-replace patterns — no logic changes.

### 7.1 `SizedBox` → `Gap`
`gap` is already in `pubspec.yaml`. Use it.

```dart
// Before
SizedBox(height: DesignTokens.spaceMd)
SizedBox(width: DesignTokens.spaceSm)

// After
Gap(DesignTokens.spaceMd)
Gap(DesignTokens.spaceSm)
```

Apply everywhere: all feature screens, all shared widgets, all bottom sheets.

### 7.2 Hard-coded colors → tokens

All direct `Color(...)`, `Colors.white`, `Colors.grey.*`, `Colors.red.*` references in widget build methods replaced with `AppColors` tokens via `Theme.of(context).extension<AppColors>()!`.

Common violations found in codebase:
- `Colors.white` → `colors.surfaceElevated` (cards) or `colors.textPrimary` (text on dark)
- `Colors.grey.shade200` → `colors.divider`
- `Colors.grey.shade300` → `colors.surfaceElevated`
- `Colors.red.shade600` → `colors.error`
- `Color(0xFF...)` hardcoded in widgets → corresponding token

### 7.3 `Navigator.push` → GoRouter

```dart
// Before
Navigator.push(context, MaterialPageRoute(builder: (_) => const ProductFormScreen()));

// After
context.goNamed(AppRoutes.productForm);
```

Add routes to `app_router.dart` for any screen currently only reachable via `Navigator.push`.

### 7.4 Local widget classes → shared `mm_*`

| Delete | Replace with |
|---|---|
| `_CategoryChip` in `catalog_screen.dart` | `MmChip` |
| `_PlanogramTile` Card+ListTile pattern | `MmListTile` / `MmListSection` |
| Inline `AlertDialog` in `planogram_list_screen.dart` | `MmDialog.show(...)` |
| Inline `AlertDialog` in `dashboard_screen.dart` | `MmDialog.show(...)` |
| Repeated eyebrow `Text(...)` in every screen | `MmEyebrow(...)` |
| `ElevatedButton.styleFrom(backgroundColor: accent)` (12 occurrences) | `MmButton(...)` |
| `OutlinedButton.styleFrom(foregroundColor: accent)` (8 occurrences) | `MmButton.outlined(...)` |
| `ElevatedButton.styleFrom(backgroundColor: errorColor)` | `MmButton.destructive(...)` |

### 7.5 File size targets

Long files broken into smaller focused units:

| File | Current lines | Target | Split strategy |
|---|---|---|---|
| `dashboard_screen.dart` | 508 | < 200 | Extract `_StoreSetupCard` → `store_setup_card.dart`, `_StatsGrid`/`_StatCard` → `stats_grid.dart` |
| `zone_detail_screen.dart` | 614 | < 250 | Extract `_MannequinSection` → `mannequin_section.dart`, `_FixtureEditSheet` → `fixture_edit_sheet.dart` |
| `catalog_screen.dart` | 283 | < 180 | Remove `_CategoryChip` (→ MmChip), simplify with `SliverAppBar` + `MmListSection` |

### 7.6 Consistent async states

All `AsyncValue.when()` blocks use the same structure:

```dart
asyncValue.when(
  data: (data) => _buildContent(data),
  loading: () => const Center(child: CircularProgressIndicator(color: colors.accent)),  
  error: (e, _) => MmEmptyState(
    icon: Icons.error_outline,
    headline: 'Something went wrong',
    body: e.toString(),
  ),
)
```

No more bare `Center(child: Text('Error: $e'))` patterns.

### 7.7 `const` constructors

All widgets with no runtime-variable parameters get `const` constructor calls at the call site. Run `dart fix --apply` as part of Agent 1 to catch these automatically.

## 11. Council Round 2 — Additions to v0.4 (2026-05-04)

After the initial screen sweep and council review, a second council audit identified the following gaps. All items below are part of v0.4 scope.

### 11.1 Dashboard (Critical — blocks ship)

**11.1.1 Remove welcome banner**
`lib/features/dashboard/dashboard_screen.dart` lines 90-128. Delete the entire gradient `Container` block (displayName + role). The store name is already in the AppBar title; the role is surfaced in the profile sheet.

**11.1.2 Logout → profile MmBottomSheet**
`dashboard_screen.dart` line 58. Replace `Icons.logout` IconButton with `Icons.account_circle_outlined` IconButton. Tapping opens an `MmBottomSheet` containing:
- Display name (16px bold)
- Role eyebrow (`MmEyebrow`)
- Store name (12px textSecondary)
- `MmButton.destructive(label: 'LOG OUT')` — shows confirmation before signing out

**11.1.3 `_StoreSetupCard` conditional**
Show only when `widthFt == null || depthFt == null || entranceJson == null`. Currently renders unconditionally for all coordinators. Card disappears once the store is fully configured.

**11.1.4 `CircularProgressIndicator` color tokens**
Add `color: AppTheme.accent` to all bare `CircularProgressIndicator()` calls across the entire `lib/features/` tree. 13 instances identified. Spinners render as dark-on-dark without this in dark environments.

**11.1.5 Remove Fixtures stat card; fold into Zones subtitle**
Coordinator stats grid currently has 6 cards. Remove the `Fixtures` card (navigates to `floorBuilder` with no context). Add `_StatItem` subtitle field; show `'${stats.fixtureCount} fixtures'` as subtitle on the Zones card.

**11.1.6 Stat badge → filled count pill**
Replace the 8px circle dot on highlighted stat cards with a count badge pill:
```dart
Container(
  padding: const EdgeInsets.symmetric(horizontal: 6, vertical: 2),
  decoration: BoxDecoration(
    color: AppTheme.accent,
    borderRadius: BorderRadius.circular(DesignTokens.radiusPill),
  ),
  child: Text('${item.value}', style: const TextStyle(color: Color(0xFFF2EFE8), fontSize: 10, fontWeight: FontWeight.w700)),
)
```

### 11.2 Screens (Important)

**11.2.1 ZoneDetailScreen AppBar slim-down**
`lib/features/zone_manager/zone_detail_screen.dart`. View-mode AppBar should be: back + title + tune icon + proposals badge icon only. Remove the Edit Floor `IconButton` from view mode — floor builder is accessible via the zone map. Edit mode AppBar already handles floor building.

**11.2.2 `_CategoryChip` → `MmChip` in CatalogScreen**
`lib/features/product_catalog/catalog_screen.dart`. Delete the `_CategoryChip` private class. Replace all 6 usages with `MmChip`. Adjust `MmChip` API if needed to support a `selected` bool with default accent/unselected colors.

**11.2.3 `ProposalReviewScreen` `_ProposalCard` → `MmCard`**
`lib/features/planogram/proposal_review_screen.dart` line 120. Replace bare `Card(...)` with `MmCard`.

**11.2.4 `MembersScreen` error state → `MmEmptyState`**
`lib/features/store/members_screen.dart` lines 134-143 and 184-192. Replace `Text('Something went wrong')` in error branches with `MmEmptyState(icon: Icons.error_outline, headline: 'Something went wrong', body: 'Pull to retry.')`.
